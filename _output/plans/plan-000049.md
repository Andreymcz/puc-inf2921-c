# Plan 000049 | feat/fala-gavea | 2026-06-15 16:37 UTC | Expose clustering params to user | Review: light
plan_format_version: 1

## Brief

User can re-generate clusters modifying algorithm params. Expose clustering params to user. Some datasets don't clusterize using default params.

## Context

`fala-gavea/app_pages/clusters.py` calls `build_cluster_df(posts)` with no parameters — all three tunable params (`n_neighbors`, `min_dist`, `min_cluster_size`) are invisible to the user and fixed at defaults. When a dataset has few posts or tightly packed embeddings, the default `min_cluster_size=5` or `n_neighbors=15` can produce a single large noise cluster (cluster_id = -1) or no meaningful separation.

`build_cluster_df` in `fala-gavea/src/fala_gavea/pipeline/cluster.py` already accepts all three params — nothing changes in the pipeline layer.

## Scope

- **In**: `fala-gavea/app_pages/clusters.py` — add param controls and pass them through
- **Out**: No changes to `pipeline/cluster.py`, `label_clusters.py`, backend, or DB

## Steps

### Step 1 — Add param controls to the clusters page

**File**: `fala-gavea/app_pages/clusters.py`

Add an `st.expander("⚙️ Parâmetros de clusterização", expanded=False)` block **above** the action buttons. Inside it, add three sliders:

```python
with st.expander("⚙️ Parâmetros de clusterização", expanded=False):
    n_neighbors = st.slider(
        "n_neighbors (UMAP)",
        min_value=2, max_value=50, value=15,
        help="Controla o balanço local/global da projeção. Reduza para datasets pequenos.",
    )
    min_dist = st.slider(
        "min_dist (UMAP)",
        min_value=0.01, max_value=0.5, value=0.1, step=0.01,
        help="Distância mínima entre pontos. Valores menores criam clusters mais compactos.",
    )
    min_cluster_size = st.slider(
        "min_cluster_size (HDBSCAN)",
        min_value=2, max_value=20, value=5,
        help="Tamanho mínimo de um cluster. Reduza se poucos posts formam grupos.",
    )
```

### Step 2 — Pass params to build_cluster_df

In the `if run_btn:` block, change:

```python
df = build_cluster_df(posts)
```

to:

```python
df = build_cluster_df(
    posts,
    n_neighbors=n_neighbors,
    min_dist=min_dist,
    min_cluster_size=min_cluster_size,
)
```

### Step 3 — Show noise feedback after clustering

After `st.success(f"{len(posts)} posts clusterizados em {n_clusters} clusters.")`, add:

```python
noise_count = int((df["cluster_id"] == -1).sum())
if noise_count > 0:
    st.info(
        f"{noise_count} posts não foram atribuídos a nenhum cluster (ruído). "
        "Se esse número for alto, reduza `min_cluster_size` ou `n_neighbors`."
    )
```

This guides the user toward the right param direction without burying them in docs.

## Acceptance Criteria

- Sliders appear in a collapsed expander before the action buttons
- Changing sliders and clicking "Gerar Clusters" re-runs with the new params
- Noise count feedback appears when any posts land in cluster_id = -1
- No changes to pipeline or backend code

## Review

**Correctness**: sliders have sensible ranges; `build_cluster_df` already guards `min(n_neighbors, len(posts) - 1)` and `min(min_cluster_size, max(2, len(posts) // 10))` so no out-of-range crashes.

**UX**: expander collapsed by default so the page doesn't look more complex for users who don't need it.
