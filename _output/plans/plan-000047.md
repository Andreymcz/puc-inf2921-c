## Brief

> agora que salvamos os embeddings na criacao dos posts, nao precisamos recalcula-los na geracao dos clusters, podemos recuperar a informaçao já salva via api.

## Context

When a post is created (via `POST /citizen_posts/` or `POST /citizen_posts/bulk`), `embed_and_store()` is called immediately, persisting the embedding to ChromaDB keyed by `post.id`.

`build_cluster_df()` in `fala-gavea/src/fala_gavea/pipeline/cluster.py` currently calls:
1. `embed_and_store(posts, vectorstore_dir)` — re-encodes all posts unconditionally
2. `get_embeddings(ids, vectorstore_dir)` — retrieves from ChromaDB

The re-encoding in step 1 is now redundant for posts that already have stored embeddings. This plan removes the redundant encoding by fetching stored embeddings first and only embedding posts that are missing from ChromaDB (graceful fallback for posts that predate the embed-on-create behavior or if the vectorstore was wiped).

## Steps

### Step 1 — Add `get_embeddings_by_id` to `embeddings.py`

In `fala-gavea/src/fala_gavea/pipeline/embeddings.py`, add a new function after `get_embeddings`:

```python
def get_embeddings_by_id(
    post_ids: list[str], vectorstore_dir: Path = DEFAULT_VECTORSTORE
) -> dict[str, list[float]]:
    """Return stored embeddings keyed by post ID. Missing IDs are omitted."""
    collection = _get_collection(vectorstore_dir)
    result = collection.get(ids=post_ids, include=["embeddings"])
    return {id_: emb for id_, emb in zip(result["ids"], result["embeddings"])}
```

Return type is `dict[str, list[float]]` so callers can detect missing IDs and reconstruct the embedding matrix in the correct order.

### Step 2 — Update `build_cluster_df` in `cluster.py`

Replace the `embed_and_store` + `get_embeddings` calls with:
1. Fetch stored embeddings via `get_embeddings_by_id(ids, vectorstore_dir)`
2. Find missing IDs (`[id for id in ids if id not in cached]`)
3. If any are missing, call `embed_and_store(missing_posts, vectorstore_dir)` and update the cache dict
4. Assemble the final `(N, D)` numpy array in `ids` order from the cache dict

Updated `build_cluster_df` body (after the early-return guard):

```python
ids = [p["id"] for p in posts]
cached = get_embeddings_by_id(ids, vectorstore_dir)

missing_posts = [p for p in posts if p["id"] not in cached]
if missing_posts:
    embed_and_store(missing_posts, vectorstore_dir)
    # refresh cache for missing ones
    new_vecs = get_embeddings_by_id([p["id"] for p in missing_posts], vectorstore_dir)
    cached.update(new_vecs)

embeddings = np.array([cached[id_] for id_ in ids])
```

Remove the old `embed_and_store(posts, vectorstore_dir)` and `embeddings = get_embeddings(ids, vectorstore_dir)` lines.

Update the import line to include `get_embeddings_by_id` in place of (or alongside) `get_embeddings`.
