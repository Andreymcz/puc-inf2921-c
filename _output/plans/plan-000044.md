## Brief

Save post embedding on post creation. Create bulk insert posts route.

## Context

The Fala Gávea backend (`fala-gavea/src/fala_gavea/`) currently embeds citizen posts only on-demand when the Streamlit frontend triggers the cluster pipeline ("Gerar Clusters"). The embedding function `embed_and_store` lives in `pipeline/embeddings.py` and is never called from the API layer.

Two gaps to close:
1. **Embedding on creation**: `POST /citizen_posts/` should call `embed_and_store` immediately after a post is saved, so the vector store stays current without requiring a manual cluster run.
2. **Bulk insert route**: `POST /citizen_posts/bulk` should accept a list of posts, save them all in one DB transaction, and embed them in one batched `embed_and_store` call — enabling efficient seeding and bulk ingestion without N sequential HTTP calls.

## Approach

- Embed call goes in the **router** (presentation layer) after the use case completes. The use case stays clean (pure domain). This is the existing pattern boundary in this codebase.
- Add `save_many` to the repository layer for efficient bulk DB writes (one commit instead of N).
- Add `BulkCreateCitizenPosts` use case that validates each input and delegates to `save_many`.
- Mock `embed_and_store` in the test client fixture so existing and new tests don't attempt to load the sentence-transformer model.

## Notes

- `embed_and_store` uses `lru_cache` for the model and collection — the model is loaded once per process. In production this means first POST after server start is slow (~5–10s depending on hardware); subsequent calls are fast.
- The `/bulk` endpoint ordering in the router (`/bulk` before `/{id}`) is critical. FastAPI matches routes in registration order and would interpret `"bulk"` as an ID string otherwise.
- Empty bulk list (`items: []`) is a valid no-op: `embed_and_store([])` already guards for empty input.
- Embedding errors (ChromaDB unavailable, model not found) bubble up as 500 from the router. A future improvement could make embedding fire-and-forget (background task), but that is out of scope for this plan.
